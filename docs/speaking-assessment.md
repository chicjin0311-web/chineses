# 중국어 말하기 평가

- 학생: `/tools/speaking` — 로그인 없이 참여코드·학번·이름 입력
- 교사: `/tools/speaking/teacher` — 기존 `classroom_private.teacher_accounts`에 등록된 이메일 인증
- 수업 도구 목록과 홈페이지에서 접근 가능

## 운영

1. 교사 이메일 인증 후 새 평가를 만든다. 기본 문항은 4·6단원 8개이며 질문·상황 안내·인정 답변을 편집할 수 있다.
2. 사진과 그림은 지도서 193쪽(교과서 69쪽), 267쪽(교과서 101쪽)에서 직접 발췌했다. 상품 3종, 음식 2종을 사용한다. 가격은 교과서 67쪽의 180위안, 70쪽의 27위안이다. 난이도를 통일하려면 평가 생성 시 한 가격을 제외한다.
3. 학생에게 링크와 참여코드를 안내한다. 별도 연습 문항은 없다. 중국어 질문은 기기의 중국어 음성으로 재생하며 질문 텍스트·뜻·병음·예시 답은 숨긴다.
4. 문항마다 최대 두 번 듣고 최대 20초 녹음한다. 녹음 시작 버튼 전 대기 시간은 제한하지 않으며 반응 속도를 자동 채점하지 않는다. 제출된 문항은 바꿀 수 없다. 업로드 실패 시 기기 IndexedDB의 대기 녹음으로 다시 저장할 수 있다.
5. 모든 문항 저장 후 최종 제출한다. 교사는 새로고침으로 현황을 확인한다.
6. 교사는 음원을 듣고 충분/부분/미확인/재확인 필요를 기록한다. 모든 문항을 판단하고 종합 근거를 적은 뒤 10~50점(5점 간격)을 확정한다. 정답 개수를 점수로 자동 변환하지 않는다. AI 자동 채점·성조 분석은 포함하지 않는다.
7. 엑셀은 성적, 문항별 기록, 평가 안내의 세 시트로 내려받는다. 음원은 교사 페이지에서 개별 내려받는다. 엑셀의 교사 페이지 URL은 로그인해야 열린다.
8. 기기 오류 시 교사가 재응시를 허용한다. 이전 녹음은 삭제하지 않고 이전 응시로 표시하며, 학생은 다시 참여코드를 입력한다.

## 접근과 저장

음원은 단기 서버 디스크가 아닌 기존 Supabase의 비공개 `speaking_private` 스키마에 bytea로 저장한다. 문항당 최대 1.8MB, 평가당 최대 100명이다. 짧은 녹음과 한 학급 규모를 위한 구현이며 장기·대규모 사용 시 객체 스토리지로 이전할 수 있다. 자동 삭제 정책은 적용하지 않았다.

학생은 HttpOnly·SameSite 쿠키의 256비트 임시 응시 토큰으로 본인 응시만 조회·제출한다. DB에는 토큰 해시만 저장한다. 참여코드로는 다른 학생의 녹음을 볼 수 없다. 교사는 Supabase의 검증된 사용자 ID와 기존 교사 허용목록, 평가 소유권을 모두 통과해야 한다. 클라이언트에 서비스 역할 키는 없다.

서버 전용 `SPEAKING_GATEWAY_SECRET`은 이 기능에만 쓰는 별도 무작위 비밀 값이다. DB에는 SHA256 해시만 저장한다. 공개 RPC는 security invoker 래퍼이며 비공개 gateway는 이 비밀 값, 학생 토큰 또는 교사 ID·소유권을 검사한다. 실제 테이블은 anon/authenticated 직접 접근이 없고 RLS로 닫혀 있다. 보안 advisor의 `rls_enabled_no_policy` 정보 항목은 이 의도된 차단 구조이다.

## 출제 후 수정
평가 상세의 `문항·사진 수정`에서 이름, 질문, 안내, 답변 예시, 사진, 가격을 편집하고 저장합니다. 참여코드는 유지됩니다. 기존 응시자의 문항 스냅샷·녹음·점수는 변경하지 않으며 이후 새 참여자만 수정본을 받습니다.
사진은 JPG/PNG/WebP 10MB 이하를 받아 최대 900px JPEG로 변환합니다. 자료당 160KB 이하, 요청 전체 약 3.3MB 제한입니다. 기존 흐린 그림을 확대해 선명하게 만들지는 못하므로 선명한 원본을 선택해야 합니다.
배포 시 `supabase/speaking-edit.sql`을 적용합니다.

## 랜덤 제시 확인
평가 상세의 `답변용 문구 · 랜덤 배정 확인`에서 후보 전체와 `랜덤 제시 미리보기`를 확인한다. 미리보기는 실제 응시를 만들거나 바꾸지 않는다. 구매 3종, 가격 2종, 음식 2종, 음료 4종에서 학생의 최초 참여 시 각각 하나를 배정하며, 같은 응시의 새로고침·이어하기에서는 기존 문항 스냅샷을 유지한다. 독립 무작위 배정이므로 학생 간 중복은 가능하다. 2026-11-02부터 봉투·결제·식사 방식·제안 반응에도 아래의 교과서 표현 후보를 제시한다.


## 나머지 네 문항의 교과서 표현 제시 (2026-11-02)
- 봉투: 需要 / 不用 — 교과서 66·67쪽. 질문에 쓰인 需要를 긍정 반응에, 본문의 不用을 부정 반응에 활용한다.
- 결제: 二维码 / 扫一下二维码 — 66·67쪽. 서로 다른 결제 방식이 아니라 같은 QR 결제의 단어/구절 힌트다. 두 후보에 동일한 답변 기준을 적용한다. 교과서에서 확인되지 않은 현금·카드·결제 앱을 추가하지 않는다.
- 식사 방식: 出去吃 / 叫外卖 — 95·100쪽 본문 질문·답변 표현을 제시한다.
- 제안 반응: 好啊 / 好的 / 行 — 각각 65·95쪽, 97쪽, 67쪽 본문. 모두 동의이며 같은 동의 의미의 다른 표현도 인정한다. 4단원의 行을 6단원 제안에 적용하는 형태다.
완성 답변 예시는 교사용이다. 제시 문구 자체가 짧은 반응이 될 수 있으므로 교사는 제시 단어와의 글자 일치가 아니라 질문과 제시 의미에 맞는 반응을 판단한다. 인정 예시에는 수업 표현을 활용한 가능한 문장도 포함되며 교과서 원문 인용만을 뜻하지 않는다.
운영 평가 템플릿의 해당 네 문항만 갱신하고, 이미 시작된 응시의 문항 스냅샷·녹음·채점은 보존한다.


## 학생별 결과 모아보기 (2026-11-02)
평가 상세의 학번순 목록에서 학번·이름을 검색한 뒤 `답변 모아보기·채점`을 누른다. 한 학생의 질문, 실제 배정 자료, 학생 답변 음원을 표로 모아 표시하며 `전체 답변 불러오기`로 저장된 음원을 불러온다. 파일을 내려받지 않아도 각 답변을 들을 수 있다. 다른 답변을 재생하면 이전 답변은 일시정지한다.
학생 목록과 상세에 최종 제출 시각(한국 시간)을 표시한다. 미제출은 ‘미제출’로 구분하며, 개별 녹음 저장 시각과 혼동하지 않는다.
전체 엑셀과 `이 학생 결과 엑셀`을 제공한다. 학번을 숫자 순서로 정렬하고 원래 학번 문자열(앞자리 0 포함)은 보존한다. 문항별 기록에는 최종 제출 시각, 녹음 저장 상태, 로그인 보호된 학생 모아보기 링크가 들어간다. 음원은 엑셀에 내장되지 않으며 자동 전사 결과도 아니다. 인정 답변 예시와 학생의 실제 답변을 구분한다.
교과서 추가 표현 재대조: 67쪽의 需要·不用·二维码·扫一下二维码·行, 95쪽의 出去吃·叫外卖·好啊, 97쪽의 好的를 학생용 교과서 영역에서 확인함. 질문의 일부를 답변에 활용하거나 다른 상황의 동의 표현을 적용한 것이며 모든 인정 예시가 교과서 원문인 것은 아니다.


## 한 학생 답변 이어 듣기
학생별 모아보기의 `처음부터 이어 듣기`는 저장된 답변을 문항 번호순으로 재생한다. 파일을 합치지 않고 하나의 오디오 재생기에서 다음 음원으로 넘어간다. 녹음 없는 문항은 건너뛰며 현재 문항과 진행 개수를 표시한다. 일시정지, 이어서 재생, 재생 종료, 처음부터 다시 듣기를 지원한다. 학생 전환·목록 이동·로그아웃·페이지 종료 시 재생을 정리하며, 개별 답변을 재생하면 이어 듣기는 일시정지한다. 네트워크 또는 브라우저 재생 제한 시 같은 문항에서 재시도할 수 있다.
검증: `node scripts/test-speaking-playlist.cjs` (순서·일시정지·누락 문항·종료·오류 복구·이전 로딩 취소).


## 반별·학번순 연속 채점
학번은 학년 1자리 + 반 1자리 + 번호 2자리의 4자리 표기를 사용한다. 예: 2101은 2학년 1반 1번, 2112는 2학년 1반 12번, 2201은 2학년 2반 1번이다. 학생 화면에도 이 예시를 안내한다. 추후 학생 안내서에도 같은 작성법과 번호 한 자리일 때 앞에 0을 붙인다는 설명을 포함한다.

`점수 저장 후 다음 채점 대기 학생`은 저장 성공과 최신 채점 상태를 확인한 뒤, 해당 평가 전체에서 제출 완료·미채점인 학생을 반별·학번 오름차순으로 선택한다. 남아 있는 가장 빠른 학번부터 시작하므로 중간에 건너뛴 학생도 빠뜨리지 않는다. 화면의 검색·제출시간 정렬은 연속 채점에 적용하지 않는다. 학생 전환 시 이전 음원 재생·캐시와 입력값을 정리한다. 미제출 학생은 제외하며 마지막 제출 학생의 채점을 저장하면 현재 제출물의 채점 완료를 안내한다. 기존 `점수 확정·저장`은 현재 학생 화면에 머무른다. 저장 실패 또는 저장 결과 재조회 실패 시 다음 학생으로 이동하지 않는다.

## 120명 / 5개 반 운영 용량 확인 (2026-11-07)
각 반 최대 29명은 서로 다른 시간대에 응시한다. 한 평가의 누적 응시 제한을 100명에서 200명으로 늘렸다. IP별 참여 요청 제한(10분당 100회), 교사 소유권 검사, 녹음 접근 권한은 기존대로 유지한다. 기존 DB는 `supabase/speaking-capacity.sql`로 현재 gateway의 해당 인원 조건만 교체한다.

분리된 점검용 평가에서 29개 독립 학생 세션으로 질문 음원 요청 290회, 20초 WAV 업로드 290회, 저장 복원 및 최종 제출 29건을 동시에 수행했다. 총 986 요청 모두 성공했으며 290개 음원의 학생·문항·파일 해시가 저장소와 일치했다. 업로드 지연 중앙값 391ms, 95백분위 723ms, 최댓값 891ms. 실제 휴대폰 29대와 교실 Wi-Fi를 측정한 결과는 아니다. 별도 용량 점검방에 100개 합성 응시를 준비하고, 실제 참여 API로 101~120번째 20명의 참여와 10문항 복원을 확인했다.
